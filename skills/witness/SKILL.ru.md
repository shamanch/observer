# Witness: доказательство вместо «готово»

## Когда применять

- **До начала работы:** зафиксировать критерии приёмки и снять базу, чтобы потом нельзя было
  подогнать критерии под результат.
- Агент закончил задачу и собирается сказать «готово», «исправлено», «проходит».
- Пользователь просит проверить, действительно ли фича работает.

## Железное правило

> Нельзя утверждать, что задача выполнена, пока `witness run` не вернул exit 0
> в этом же сообщении. Ручные критерии (`skip`) доказательством не считаются.

Если проверка не запускалась — говорите «не проверено», а не «должно работать».

## Порядок

1. **Проверьте CLI.**
   ```bash
   witness --version
   ```
   Если команды нет — остановитесь. Ничего не устанавливайте и не запускайте пакетный
   менеджер: покажите человеку инструкцию по установке из README проекта и дождитесь
   его подтверждения. Установка ПО — решение человека, а не агента.

2. **Инициализация.**
   ```bash
   witness init
   ```
   Если `.witness/` уже есть — не перезаписывайте настройки.

3. **Критерии приёмки — с человеком.**
   ```bash
   witness claim "<задача>"
   ```
   Покажите критерии и попросите человека утвердить. **Не используйте `--yes`**,
   если человек не подтвердил критерии явно: смысл продукта в том, что их утверждает человек, а не модель.

4. **База до работы.**
   ```bash
   witness run --baseline
   ```
   Приложение должно быть запущено. Если адрес нестандартный — `--base-url http://127.0.0.1:<порт>`.
   База нужна, чтобы отличить настоящую проверку от тавтологии.

   **Если работа началась или закончилась до загрузки навыка**, честной базы уже нет.
   Скажите об этом прямо, всё равно прогоните проверки и напишите
   «базы нет: сравнение до/после недоступно». Никогда не запускайте `--baseline` задним
   числом: это выдаст готовое приложение за исходное состояние и подделает differential.

5. **После работы.**
   ```bash
   witness run
   ```
   Читайте не только итог, но и `detail` упавших критериев и блок `differential`.

6. **Доказательство.**
   ```bash
   witness report   # .witness/report.html
   witness badge    # .witness/badge.svg + badge.json
   ```

Если агент запускается одной командой, используйте `witness wrap -- <команда>`:
он выполнит работу и сразу прогонит проверку. Код агента важнее кода проверки.

## Что запрещено

- Ослаблять критерии после прогона, удалять проверки, ставить `required: false`, чтобы получить зелёный.
- Запускать `--baseline` после работы, чтобы подделать сравнение до/после.
- Считать `skip` (ручные шаги) доказательством выполнения.
- Проверять соседний маршрут, если в задаче назван другой.
- Пересказывать отчёт агента вместо вывода `witness run`.
- Говорить «тесты прошли», если в этом сообщении не было запуска.

## Формат ответа

```
Проверка: witness run → exit 0
Критериев: 4, машинных: 3, ручных: 1
Прошло: 3/3 машинных
Тавтологии: нет
Отчёт: .witness/report.html
```

Если exit != 0:

```
Проверка: witness run → exit 1
Упало:
- <критерий>: <detail>
Что делать: <конкретное действие>
```

Если проверки шли без базы, формат тот же, но в строке проверки добавьте
`(базы нет: сравнение до/после недоступно)`.

## Границы

Witness проверяет только то, что записано в критериях. Он не заменяет code review,
не ищет уязвимости и не оценивает качество кода. Зелёный badge означает
«утверждённые проверки прошли», а не «продукт хороший».
